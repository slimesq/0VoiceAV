# 两路音频混流与时间同步

> 第43节补充讲义 05 · 承接第8章音频解码与重采样、第9章AAC与封装、第10章amix

本讲把两路声音变成一路可播放、可编码的声音，并连接到 MP4 输出和 RTC 时间轴。
先跑离线文件，再理解实时输入多出的时钟、迟到和断流问题。

## 1 先明确混流发生在哪一层

| 操作 | 输入与输出 | 典型用途 |
| --- | --- | --- |
| 音频混音 | 两路PCM → 一路PCM | 人声与背景音乐、多人会议 |
| 声道合并 | 多路输入声道 → 一路多声道音频 | 用 `amerge` 等组合声道 |
| 视频合成 | 多幅图像 → 一幅图像 | 画中画、宫格布局 |
| 复用封装 | 视频packet与音频packet → 一个容器 | MP4、FLV等 |

不能把两路 AAC 压缩字节直接相加，也不能通过把两个 AAC packet 交替写进一条轨道来混音。
需要先分别解码为 PCM，在共同时间轴上混合，再编码输出。
两路视频如果要同时出现在同一画面，还要另做视频合成；本讲只展开音频混音。

```text
输入A → 解封装 → 音频解码 → PCM ─┐
                                 ├→ 格式与时间协调 → amix → PCM → AAC编码 ─┐
输入B → 解封装 → 音频解码 → PCM ─┘                                       ├→ MP4
选定的主视频 ─────────────────────── 保留原编码或重新编码 ─────────────────┘
```

## 2 混合前要统一什么

| 属性 | 示例差异 | 处理方式 |
| --- | --- | --- |
| 采样率 | 44.1 kHz与48 kHz | 重采样到选定输出时钟 |
| 采样格式 | S16、FLT、FLTP | 转成滤镜支持的格式 |
| 声道布局 | mono、stereo | 明确映射，不能只比较声道数量 |
| 起始时间 | A从0秒开始，B从0.1秒开始 | 保留或明确重建相对偏移 |
| 每次送入的长度 | 480、960、1024采样点 | 按PTS和样本数量处理，不要求每次等长 |

格式一致只是前提。`amix` 主要从各输入的样本队列中取数据相加，不会仅凭第二路PTS较晚，
就自动给它补足前面的静音。要让两段声音真正对齐，输入队列中的样本也必须对应同一段时间。

FFmpeg 7.1 的 `amix` 使用浮点采样。输入为整数时，滤镜协商可以自动插入重采样器
进行转换；`aformat` 用于约束协商结果，实际转换由图中相应组件完成。
可核对[FFmpeg 7.1.3 滤镜文档](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n7.1.3/doc/filters.texi)中的 `amix` 和 `aformat`。

packed 与 planar 还影响内存布局：双声道 packed 是 `L0 R0 L1 R1...`，
planar 是左右声道分别存储。AAC 编码器常用 FLTP，但应查询实际编码器支持格式，
不能把解码器输出或滤镜输出直接当成固定的 S16。

## 3 混音的数值意义

在同一时刻，对应声道的采样值进行加权求和：

```text
不归一化：y[n] = gA × A[n] + gB × B[n]

两路都活跃、正权重且normalize=1的稳态示意：
y[n] = (wA × A[n] + wB × B[n]) / (wA + wB)
```

例如 A、B 的某个采样都是0.8，直接相加得到1.6，超出了常用归一化音频的标称范围。
转成有限范围整数 PCM 等环节时可能削波，听感上出现失真。

`weights='1 0.25':normalize=1` 表示活跃的两路权重比为4:1；不能理解为最终人声保持原音量、
背景音乐固定为原音量的25%。当某路结束时，归一化权重还可能调整。
本例两路都活跃时，音乐系数为 `0.25/1.25=0.2`；人声结束并完成归一化调整后，
只剩音乐时系数变为1。因此，背景音乐可能变响，而不是一直保持原来的混合系数。
需要固定增益时，可以选择明确的音量系数和 `normalize=0`，同时保留峰值余量，
必要时加入限幅器；限幅器也可能引入需要考虑的处理延迟。

这里“活跃”指混音器的输入状态，不等于检测到有人说话。一条输入持续送静音帧时，
并不会因此自动退出归一化权重；语音活动检测和动态音量策略需要由上层决定。

## 4 最小离线混音实验

按[本章入口](../README.md)生成 `voice.wav` 和 `music.wav`：前者2秒、48 kHz双声道，
后者3秒、44.1 kHz单声道。在实验目录执行：

```powershell
ffmpeg -y -i voice.wav -i music.wav -filter_complex "[0:a]aresample=48000,aformat=sample_fmts=fltp:channel_layouts=stereo,asetpts=PTS-STARTPTS[a0];[1:a]aresample=48000,aformat=sample_fmts=fltp:channel_layouts=stereo,asetpts=PTS-STARTPTS[a1];[a0][a1]amix=inputs=2:duration=longest:dropout_transition=0:weights='1 0.25':normalize=1[mix]" -map "[mix]" -c:a aac -ar 48000 -ac 2 mixed.m4a
ffprobe -v error -show_entries stream=codec_name,sample_rate,channels,duration -of default=noprint_wrappers=1 mixed.m4a
```

预期得到约3秒、48 kHz、双声道 AAC。AAC 有编码延迟和尾部处理，验证时需要结合
容器时间信息及有效样本，而不是只数压缩 packet 的个数。

这条命令把两路文件各自起点归零，表示“把两段文件从各自开头同时播放”。
**已有相对时间关系的录音或 RTC 输入不能直接照搬这个归零策略**，否则原有偏移会消失。

### 4.1 duration 与结束条件

| `amix`选项 | 含义 | 本例时长 |
| --- | --- | --- |
| `longest` | 以最长输入为准 | 约3秒 |
| `shortest` | 以最短输入为准 | 约2秒 |
| `first` | 以第一路输入为准 | 约2秒 |

`dropout_transition` 是某路结束时重新归一化音量的过渡时间，不是网络断流超时。
本例设0是为了直接观察结束行为；连续节目通常还要考虑音量变化是否突兀。

### 4.2 把第二路声音实际延迟100 ms

`asetpts` 修改的是时间标签，不会生成静音样本。若希望音乐比人声晚100 ms开始，
应在共同起点的输入上实际补入100 ms静音，例如使用 `adelay`：

```powershell
$mixGraph = "[0:a]aresample=48000,aformat=sample_fmts=fltp:channel_layouts=stereo,asetpts=PTS-STARTPTS[a0];"
$mixGraph += "[1:a]aresample=48000,aformat=sample_fmts=fltp:channel_layouts=stereo,asetpts=PTS-STARTPTS,adelay=100:all=1[a1];"
$mixGraph += "[a0][a1]amix=inputs=2:duration=longest:dropout_transition=0:weights='1 0.25':normalize=1[mix]"
ffmpeg -y -i voice.wav -i music.wav -filter_complex $mixGraph -map "[mix]" -c:a aac -ar 48000 -ac 2 mixed_delayed.m4a
ffprobe -v error -show_entries stream=sample_rate,channels,duration -of default=noprint_wrappers=1 mixed_delayed.m4a
```

`adelay` 此处单位为毫秒，`all=1` 将同样的延迟应用到全部声道。
在48 kHz下等于每声道补4800点静音，本例输出约3.1秒。
若使用代码维护输入队列，同样需要根据共同时间轴补静音或裁掉过早的数据；
不能只把第二路 `frame->pts` 加4800，仍把它的第一批声音样本立即交给 `amix`。

对比实验中，将一段短信号只做 `asetpts=PTS+0.1/TB` 再与静音混合，非零样本仍从第0点开始；
改为 `adelay=100:all=1` 后，首个非零样本位于第4800点。
可结合[amix样本队列实现](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n7.1.3/libavfilter/af_amix.c)
理解为什么时间标签与样本对齐必须分别处理。

## 5 对照第10章 AudioMixer

现有[音频混音示例](../../../../voice_av/10-ffmpeg-filtering/03-audio-mix/src/audiomixer.cpp)
已经建立这条图：

```text
abuffer input_0 ─┐
                 ├→ amix → aformat → abuffersink
abuffer input_1 ─┘
```

阅读时按四个位置查找：

1. `init()`：为每路输入设置采样率、格式、布局以及 `time_base=1/sample_rate`。
2. `addFrame()`：按 `size / (channels × bytes_per_sample)` 计算每声道采样点数，
   分配带引用计数缓冲区的 frame，并设置 `pts = next_pts`。
3. 成功送入后：`next_pts += nb_samples`。双声道也只递增每声道采样点数，不能再乘2。
4. 结束时：每路各自 `av_buffersrc_close()`，sink继续读取直到EOF。

现有接口只接受 packed PCM。为复用它，将两路实验 WAV 转成它要求的输入：

```powershell
ffmpeg -y -i voice.wav -ar 48000 -ac 2 -f f32le voice_48k_f32.pcm
ffmpeg -y -i music.wav -ar 48000 -ac 2 -f s16le music_48k_s16.pcm
..\..\..\build\cmake\Debug\voice_av_10_03_audio_mix.exe voice_48k_f32.pcm music_48k_s16.pcm mixed_96k_s16.pcm longest
ffplay -f s16le -ar 96000 -ac 2 mixed_96k_s16.pcm
```

该程序输出固定为96 kHz双声道 S16，本例结果为：

```text
3秒 × 96000采样点/秒/声道 × 2声道 × 2字节/采样 = 1,152,000字节
```

它采用两路等权归一化；与前面4:1权重的命令不是同一音量配置。
输出是裸 PCM，播放参数必须与实际输出一致，不能按输入的48 kHz播放。

## 6 时间基与采样计数

48 kHz 音频使用 `time_base = 1/48000` 时：

| PCM块 | `nb_samples` | 起始PTS | 持续时间 |
| --- | --- | --- | --- |
| 第1块 | 960 | 0 | 20 ms |
| 第2块 | 960 | 960 | 20 ms |
| 第3块 | 960 | 1920 | 20 ms |

这是每声道采样点数；立体声不会变成每块1920个 PTS 刻度。
`AVFrame.nb_samples` 表示这帧音频每声道有多少采样点，不表示采样率，也不表示字节数。

当输入是无间断、共同起点的离线 PCM，可以按累计样本数生成 PTS。
当输入来自解码 packet，应先按对应时间基解释 frame 时间戳，再转换到输入滤镜要求的时间基。
共同时间轴上的“B比A晚100 ms”，在48 kHz时对应4800个刻度；
如第4.2节所示，要同时用样本填充或裁剪落实这个偏移。

sink输出的时间基用 `av_buffersink_get_time_base()` 获取，不要把某个输入时间基
直接套给输出。进入 AAC 编码器前，frame PTS 再从 sink 时间基换算到编码器时间基。

第10章的 `getFrame()` 返回裸字节，适合当前离线示范，但会丢掉 frame 自带的时间信息。
扩展到 RTC 或带偏移的转码时，接口宜返回 `AVFrame`，或同时返回 PTS、时间基、
实际采样点数和格式；不能只传一个 byte buffer，就期待同步信息自动保留下来。

## 7 混音输出如何交给 AAC 编码器

滤镜输出一帧有多少采样点，由输入与调度共同影响；AAC 编码器又有自己的输入要求。
常见 AAC-LC 编码帧为每声道1024点，但程序应在打开编码器后读取 `frame_size`，
并结合 `AV_CODEC_CAP_VARIABLE_FRAME_SIZE`、`AV_CODEC_CAP_SMALL_LAST_FRAME` 判断送入规则。

推荐增加一个 `AVAudioFifo`，下面按固定帧长且 `frame_size > 0` 描述控制流程，
不是可单独编译的完整程序。可变帧长编码器按自身规则选块，不能把0当成FIFO循环阈值。

```text
sink收到混音frame
  → 如有必要，转换为编码器采样率、格式、声道布局
  → 将extended_data中的有效样本写入FIFO
  → FIFO样本数达到编码器所需长度时：
       分配或复用编码frame
       读出所需样本
       设置frame.pts，送编码器
       按实际送入的nb_samples推进下一帧PTS
       循环收packet，重缩放时间戳后交muxer
```

FIFO 主要缓存样本，不自动保存整条媒体时间线。需要另外维护首个有效样本的 PTS、
连续性和剩余样本的位置。对实时缺口应先决定补静音、等待或丢弃，再写入连续 FIFO。
API 可查看本地 `third_party/ffmpeg-src/libavutil/audio_fifo.h`。

创建FIFO时应使用最终编码器的采样格式和声道数；`av_audio_fifo_size()` 及读写长度的
单位都是每声道采样点数，不是字节。`AVFrame` 则设置 `sample_rate`、`format`、
`ch_layout` 和 `nb_samples` 后分配缓冲区，再读入样本，避免把FLTP按交错数据复制。

最后不足一帧时，FFmpeg 7.1 的发送接口允许最后一帧短于 `frame_size`；
编码器若不直接支持小尾帧，内部可按相应规则补齐。按实际编码器能力处理，不要无条件丢掉尾块，
也不要在应用层和编码器层重复补齐。需要手工补齐时，还要区分真实样本长度与填充长度。
短尾帧只在真实输入结束时提交，不是实时输入暂时不足一帧时就提交。
接口与内部处理可对照本地 `libavcodec/avcodec.h` 和 `libavcodec/encode.c`。

## 8 完整结束顺序

两路输入可能在不同时间结束，因此要分别排空。下面按 `duration=longest` 描述：

```text
输入A结束 → 排空解码器A → 排空A的前置独立重采样器（如有）
         → 送完A的尾部PCM → 关闭abuffer A
输入B结束 → 排空解码器B → 排空B的前置独立重采样器（如有）
         → 送完B的尾部PCM → 关闭abuffer B
→ 持续读取滤镜输出直到EOF
→ 排空混音后的独立重采样器（如有）
→ 处理FIFO尾部
→ 向AAC编码器送NULL并收包直到EOF
→ 视频路径也已完成、相关编码器均已排空 → 写容器trailer
```

一路结束后，另一路仍可继续；送输入期间也要持续读sink，不是等全部文件读完才开始取输出。
若重采样由滤镜图内部负责，关闭source后继续读sink，会推进其排空。
独立 `SwrContext` 的尾部样本必须交给它实际连接的下游，所以位于source前时要先排空再关source，
位于sink后时则在图结束后、FIFO收尾前排空。
`shortest/first` 可能使图提前结束，应用应据此停止不再需要的输入。
`EAGAIN` 表示当前需要推进另一侧，不等于输入结束；不要据此写 trailer。

## 9 保留一路视频并替换为混音音轨

实验目录已有2秒的 `sample_hevc.mp4` 和两段音频。下面保留视频编码，生成一条新的混音音轨：

```powershell
ffmpeg -y -i sample_hevc.mp4 -i voice.wav -i music.wav -filter_complex "[1:a]aresample=48000,aformat=sample_fmts=fltp:channel_layouts=stereo,asetpts=PTS-STARTPTS[a0];[2:a]aresample=48000,aformat=sample_fmts=fltp:channel_layouts=stereo,asetpts=PTS-STARTPTS[a1];[a0][a1]amix=inputs=2:duration=longest:dropout_transition=0:normalize=1[mix]" -map 0:v:0 -map "[mix]" -c:v copy -c:a aac -ar 48000 -ac 2 -shortest mixed_av.mp4
```

`-c:v copy` 只表示视频不重编码；音频仍然经过混音和 AAC 编码。
这里的 `-shortest` 控制最终输出流的结束策略，和 `amix:duration=shortest` 位于不同层。
换成其他输入时，视频与混音轨道的时长关系应由产品需求决定。

项目[第9章 muxer](../../../../voice_av/09-ffmpeg-encoding-and-muxing/05-mp4muxer-5/src/muxer.cpp)
已有 packet 时间戳重缩放的写包位置。连接时分别用音、视频各自编码器的时间基转换到各自轨道，
不要求音视频共享一个数值相同的时间基。

## 10 从离线混音走向 RTC

离线文件可以一直等待另一条输入；RTC 需要稳定输出节拍。
例如以48 kHz、20 ms为节拍，每次要输出960点/声道，输入少了也不能无限等下去。

| 情况 | 需要的策略 |
| --- | --- |
| 网络乱序与短时抖动 | 每路独立抖动缓冲，按媒体时间排序与限时等待 |
| 某路临时无声或丢包 | 按策略补静音或做丢包隐藏，保持输出节拍 |
| 某路迟到 | 按期限丢弃或调整，避免队列无限增长 |
| 设备采样时钟漂移 | 依据共同输出时钟估计误差，做渐进重采样补偿 |
| 某人真正离开 | 执行结束或移除策略，处理归一化与音量变化 |

临时缺包与永久 EOF 不同。`av_buffersrc_close()` 表示这个 source 结束，不能把它当成
每次缺包时的占位方式。`amix` 也不自动提供网络抖动缓冲、AEC、时钟同步或活跃说话人策略。

## 11 自测

1. 为什么两路48 kHz双声道 AAC 不能直接在压缩层混合？
2. 每声道960点的双声道 FLT 块有多少字节，PTS推进多少？
3. 为什么 `asetpts=PTS-STARTPTS` 可能破坏两路原本的同步？
4. 为什么 `amix` 已输出PCM，还可能需要音频 FIFO？
5. 为什么只改第二路PTS不能替代补静音？前置独立重采样器应在什么时候排空？

参考答案：AAC字节不是可直接相加的采样；块大小为 `960×2×4=7680` 字节，
在 `1/48000` 时间基下 PTS推进960；分别归零会抹掉原有起始偏移；
滤镜输出块长度不一定等于编码器要求的帧长，而FIFO可重新组织样本。
第5题：`amix`不会替第二路自动补出相应静音；前置重采样器要在关闭其下游source之前排空。
